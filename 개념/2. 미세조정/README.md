# 2. 미세조정

미세조정(Fine-tuning)은 대규모 원시 텍스트로 사전 훈련된 기반 모델의 가중치를 특정 도메인이나 작업에 맞게 추가로 학습하는 과정이다. 모델이 이미 습득한 언어 능력을 유지하면서 사용자의 지시를 이해하거나, 전문 용어를 다루거나, 정해진 출력 형식을 따르는 능력을 강화한다.

## 2.1 미세조정이 필요한 이유

기반 모델은 일반적인 문장 생성 능력은 갖추고 있지만 다음과 같은 한계가 있을 수 있다.

- 사용자가 요구한 작업과 출력 형식을 정확히 인식하지 못한다.
- 전문 분야의 용어, 로그 패턴 또는 업무 규칙을 충분히 알지 못한다.
- 근거가 없거나 틀린 정보를 사실처럼 생성하는 환각(Hallucination)이 발생한다.
- 답변의 형식과 품질이 요청마다 일관되지 않을 수 있다.

미세조정은 모델의 행동과 출력 형식을 원하는 방향으로 유도할 수 있지만, 사실 정확성을 자동으로 보장하지는 않는다. 최신 지식이나 검증 가능한 사실이 중요한 경우에는 검색 증강 생성(RAG), 외부 도구, 인용 검증과 함께 사용해야 한다.

## 2.2 전체 미세조정과 PEFT

### 전체 모델 미세조정

사전 학습된 모델의 모든 파라미터를 새로운 데이터로 업데이트한다.

- 장점: 데이터와 연산 자원이 충분하면 모델 전체를 도메인에 맞게 세밀하게 조정할 수 있다.
- 단점: GPU 메모리와 학습 비용이 매우 크며, 데이터가 부족하면 과적합이나 기존 능력의 망각이 발생할 수 있다.

### 효율적 미세조정(PEFT)

대부분의 기존 가중치는 고정하고 일부 파라미터만 학습한다. 대표적인 방식이 LoRA(Low-Rank Adaptation)다.

LoRA는 attention 등의 기존 가중치 행렬을 직접 모두 수정하는 대신 작은 저랭크 행렬을 추가해 변화량을 학습한다.

```text
기존 출력:       y = Wx
LoRA 적용 출력: y = Wx + BAx
```

여기서 `W`는 고정된 기존 가중치이고 `A`, `B`만 학습한다.

- 장점: 전체 미세조정보다 필요한 GPU 메모리와 저장 공간이 작다.
- 장점: 작업별 어댑터를 별도로 보관하고 교체할 수 있다.
- 단점: 모든 작업에서 전체 미세조정과 같은 성능을 보장하지 않는다.
- 단점: LoRA의 rank, 적용 계층, 학습률과 데이터 품질에 따라 성능이 크게 달라진다.

QLoRA는 기반 모델을 4비트 등으로 양자화해 저장하고 LoRA 어댑터를 학습함으로써 메모리 사용량을 더 줄이는 방식이다.

## 2.3 목적에 따른 학습 방식

### 1. 지도 미세조정(SFT)

기반 모델을 사용자의 지시를 따르는 모델로 조정한다. 일반적으로 지시문, 입력 문맥, 모범 답변으로 구성된 질문-답변 쌍을 사용한다.

```json
{
  "instruction": "다음 보안 로그를 분석하고 위험도를 JSON으로 출력하라.",
  "input": "로그 내용",
  "output": {
    "risk_level": "high",
    "attack_type": "SQL injection",
    "evidence": ["탐지 근거"],
    "recommended_action": ["대응 방법"]
  }
}
```

Decoder-only LLM에서는 전체 시퀀스를 한 칸씩 이동한 Causal LM Loss를 사용한다. 다만 지시문까지 정답으로 학습시키기보다 모범 답변 영역에만 손실을 적용하는 response-only loss 구성이 흔하다. 이렇게 하면 모델이 프롬프트를 복제하기보다 답변 생성에 집중한다.

### 2. 도메인 적응 추가 사전학습(DAPT)

특정 전문 영역의 대규모 비라벨 텍스트를 다음 토큰 예측 방식으로 추가 학습한다. 보안 로그, 보안 보고서, CVE 설명, 운영 절차와 같은 자료를 통해 도메인 용어와 문체를 모델 가중치에 내재화하는 데 목적이 있다.

- 데이터: 대규모 도메인 원문
- 학습 방식: 자기지도학습
- 손실 대상: 전체 텍스트의 다음 토큰
- 주의점: 원문의 품질, 개인정보, 비밀정보, 라이선스와 데이터 중복을 사전에 검토해야 한다.

DAPT는 모델이 지시를 잘 따르게 만드는 학습과 목적이 다르다. 실무에서는 DAPT로 도메인 표현을 익힌 뒤 SFT로 진단 절차와 출력 규격을 학습시키는 순서를 사용할 수 있다.

### 3. 작업 특화 미세조정

모델을 단일 분류·판별 작업에 최적화한다. Transformer의 hidden state 위에 분류 헤드를 추가하고 범주 라벨을 예측하도록 학습할 수 있다.

- 입력: 텍스트 또는 로그
- 정답: 정상, SQL 삽입, XSS, 경로 조작 등의 범주 라벨
- 대표 손실: Cross-Entropy Loss
- 활용: 공격 유형 분류, 위험 등급 판정, 스팸·이상 로그 탐지

생성형 모델이 반드시 필요한지 먼저 판단해야 한다. 출력이 고정된 범주 하나라면 생성형 LLM보다 분류 모델이 더 빠르고 일관적일 수 있다.

## 2.4 보안 로그 분석 LLM 설계 예시

로그 기반 네트워크 위험 분석 시스템이라면 다음과 같은 조합을 고려할 수 있다.

```text
보안 도메인 원문 수집·비식별화
    ↓
도메인 적응 추가 사전학습(DAPT)
    ↓
정형화된 분석 대화쌍으로 지도 미세조정(SFT/LoRA)
    ↓
실시간 자산·정책·위협 정보 RAG
    ↓
스키마 검증 및 보안 전문가 검토
```

### 핵심 데이터

1. **정상 로그와 오탐 해소 데이터**
   - 정상 트래픽, 관리 작업, 헬스 체크, 백업 및 배포 로그
   - 탐지 규칙이 경보를 발생시켰지만 실제 공격이 아니었던 사례
   - 정상과 공격을 구분한 근거

2. **대표 웹 공격과 침투 시도 로그**
   - SQL 삽입(SQL Injection)
   - 크로스 사이트 스크립팅(XSS)
   - 경로 조작(Path Traversal)
   - 브루트포스 및 계정 탈취 시도
   - 명령어 삽입, 악성 파일 업로드 등의 공격

3. **다단계 공격 시나리오**
   - 정찰 → 초기 침투 → 권한 상승 → 내부 이동 → 정보 유출
   - 서로 다른 시간과 장비에서 발생한 이벤트의 연결 관계
   - 공격 단계별 근거, 불확실성 및 권장 대응

학습 데이터에는 원본 비밀번호, 세션 토큰, API 키, 개인정보와 내부 IP 등 민감정보가 포함될 수 있으므로 비식별화, 접근 통제, 보존 기간과 학습 데이터 계보를 관리해야 한다.

### 권장 출력 규격

자유 형식 설명만 생성하게 하면 후속 시스템이 결과를 안정적으로 처리하기 어렵다. JSON Schema 등으로 다음 항목을 고정할 수 있다.

- 위험 수준과 신뢰도
- 추정 공격 유형
- 판단 근거가 된 로그 구간
- 영향받은 자산
- 추가로 필요한 정보
- 즉시 대응 및 장기 대응
- 판단 불가 여부

모델이 증거가 부족할 때 추측하지 않고 `판단 불가` 또는 `추가 정보 필요`를 출력하도록 학습 데이터에 충분히 포함해야 한다.

## 2.5 Hugging Face 모델 유형

Hugging Face에서 모델을 선택할 때 저장소 이름과 모델 카드를 확인해야 한다.

- **Base 모델**: 대규모 말뭉치의 다음 토큰 예측을 통해 사전 훈련된 기반 모델이다. 일반적으로 별도의 대화 템플릿 없이 지시 수행 능력이 충분하지 않을 수 있다.
- **Instruct 또는 Chat 모델**: 지도 미세조정과 선호 정렬 등을 거쳐 사용자의 지시와 대화 형식을 따르도록 조정된 모델이다. 일반적인 AI Agent의 시작점으로 더 적합한 경우가 많다.
- **Embedding 모델**: 텍스트를 의미 벡터로 변환해 검색, 군집화와 유사도 계산에 사용한다. 일반적인 문장 생성 모델과 목적 및 출력이 다르다.

`transformers`와 PyTorch를 사용해 모델과 토크나이저를 불러올 수 있다. 모델마다 BOS, EOS, PAD 같은 특수 토큰과 chat template이 다르므로 해당 모델의 설정을 그대로 따라야 한다.

## 2.6 데이터셋 준비

기존 모델이 학습된 대화 형식과 chat template에 맞춰 데이터를 직렬화한다.

```text
system: 역할과 안전 규칙
user: 질문 또는 로그
assistant: 검증된 모범 답변
EOS
```

데이터 품질 관리에서 중요한 항목은 다음과 같다.

- 중복되거나 거의 같은 질문-답변 쌍 제거
- 사실 오류, 모순, 오래된 정책과 잘못된 라벨 검수
- 학습·검증·테스트 세트 사이의 데이터 누수 방지
- 짧고 쉬운 사례뿐 아니라 모호한 사례와 판단 불가 사례 포함
- 실제 운영 분포에 맞춘 정상·공격·오탐 비율 구성
- 개인정보와 비밀정보 제거
- 모델이 따라야 할 출력 스키마를 일관되게 유지

## 2.7 학습과 평가 과정

```text
1. 목적과 성공 기준 정의
2. Base 또는 Instruct 모델 선정
3. 파인튜닝 전 기준 성능 평가
4. 데이터셋 정제·분할·템플릿 적용
5. LoRA 또는 전체 미세조정 수행
6. 검증 세트로 과적합과 학습 상태 확인
7. 파인튜닝 전·후 동일 테스트 세트 비교
8. RAG 결합 후 다시 평가
9. 안전성 검토와 제한된 배포
10. 운영 로그 기반 지속 평가
```

단순히 손실값이 낮아졌다는 이유만으로 성공했다고 판단하면 안 된다. 다음 지표를 함께 비교한다.

- 작업 성공률과 지시 준수율
- 분류 Precision, Recall, F1 및 혼동 행렬
- 근거 없는 주장과 환각 비율
- JSON 등 출력 스키마 준수율
- 정상 로그의 오탐률과 공격 로그의 미탐률
- 응답 지연시간, 처리량과 GPU 메모리
- 미세조정 이전의 일반 능력이 유지되는지 여부

## 2.8 LoRA와 RAG의 차이

LoRA와 RAG는 서로 대체하는 기술이 아니라 해결하는 문제가 다르다.

| 구분 | LoRA 미세조정 | RAG |
| --- | --- | --- |
| 주요 목적 | 행동, 문체, 절차와 출력 형식 학습 | 외부 문서와 최신 사실 제공 |
| 지식 위치 | 모델 어댑터 가중치 | 검색 데이터베이스 |
| 정보 갱신 | 재학습 또는 어댑터 교체 필요 | 문서 색인 갱신으로 가능 |
| 출처 인용 | 자체적으로 보장하지 않음 | 검색 문서와 연결 가능 |
| 적합한 예 | 로그 진단 방식과 JSON 출력 학습 | 최신 CVE, 자산 정보, 내부 정책 검색 |

보안 분석 시스템에서는 **LoRA로 분석 절차와 출력 형식을 학습하고, RAG로 최신 위협 정보와 조직 내부 지식을 제공하는 조합**이 실용적이다.

미세조정이 RAG의 검색 성능 자체를 자동으로 높이는 것은 아니다. RAG 성능은 임베딩 모델, 청킹, 메타데이터 필터, 검색 방식과 재순위화에 크게 좌우된다. 다만 미세조정을 통해 모델이 검색 질의를 더 잘 만들고, 검색된 근거를 따르며, 근거가 없을 때 답변을 유보하도록 개선할 수 있다.

## 2.9 모델 규모와 배포 방식

AI Agent의 품질은 모델 크기만으로 결정되지 않는다. 데이터 품질, 도구 사용 능력, RAG 구성, 추론 설정과 평가 체계가 함께 영향을 준다.

- **대형 상용 모델 API**: 일반 추론 능력과 운영 편의성이 좋을 수 있지만 외부 전송, 비용, 지연시간과 공급자 의존성을 검토해야 한다.
- **목적 특화 로컬 모델**: 데이터와 인프라를 내부에서 통제할 수 있지만 GPU, 서빙 최적화, 보안 패치와 품질 검증을 직접 담당해야 한다.

작은 모델을 고품질 데이터와 제한된 작업에 맞춰 조정하면 특정 업무에서는 효율적일 수 있지만, 복잡한 범용 추론에서는 더 큰 모델이 유리할 수 있다. 실제 운영 데이터로 비교 평가한 뒤 선택해야 한다.

## 2.10 Large Language Diffusion Model

Large Language Diffusion Model은 자기회귀 모델처럼 왼쪽에서 오른쪽으로 한 토큰씩 생성하는 대신, 잡음이 섞이거나 마스킹된 토큰 시퀀스를 여러 단계에 걸쳐 복원하는 방식의 언어 모델 계열이다.

이는 미세조정이나 RAG의 대체 개념이 아니다.

- 확산형 언어 모델도 목적에 맞게 미세조정할 수 있다.
- 외부 지식이 필요하면 RAG를 결합할 수 있다.
- 병렬 생성 가능성이 있지만 실제 속도와 품질은 모델 구현과 반복 복원 단계에 따라 달라진다.
- 일반적인 Hugging Face 자기회귀 LLM의 학습 코드와 동일하게 적용된다고 가정하면 안 된다.

## 2.11 환각을 줄이기 위한 원칙

미세조정만으로 환각을 제거할 수는 없다. 다음 방법을 함께 적용한다.

1. 검증된 정답과 근거가 포함된 고품질 SFT 데이터 사용
2. 최신 정보와 내부 자료는 RAG 또는 도구로 조회
3. 답변에 사용한 로그, 문서와 규칙의 출처 표시
4. 증거가 부족하면 답변을 유보하도록 학습
5. 구조화된 출력과 스키마 검증 적용
6. 고위험 판단은 보안 전문가가 최종 검토
7. 배포 후 실제 오답과 오탐을 수집해 회귀 평가 세트로 관리
